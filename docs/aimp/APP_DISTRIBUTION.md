# Desktop and mobile apps: how they are built and shipped

Status (22 Nov 2026): the folders and configs exist and the safety rules are tested. **No installer or phone app has been built yet**, because that needs tools and accounts this session does not have (Xcode, Android Studio, code-signing certificates). Nothing here has been run on a real device.

## The approach: one app, thin shells

AiMoneyPrinter stays one web app (`apps/web`). The desktop and phone apps are thin wrappers that open the hosted app. They hold no keys and no business logic, so a fix to the web app reaches every platform at once.

| Piece | Folder | Technology | Output |
|---|---|---|---|
| Installable web app (works today) | `apps/web` (`app/manifest.ts`) | PWA, "Add to Home Screen" | Nothing to build |
| Desktop | `apps/desktop` | Electron | Mac `.dmg`, Windows `.exe` installer, Linux AppImage |
| iPhone and Android | `apps/mobile` | Capacitor | Xcode and Android Studio projects, then `.ipa` / `.aab` |

## Before any wrapper works

1. **Deploy the web app to a public https address** (for example on Vercel). The wrappers load that address. They cannot run the app on their own.
2. Real sign-in and a real database must be in place first. Today the app is on demo storage and the business id comes from the browser (see `claude/aimp-launch-gap-audit.md`).

## Desktop (Electron)

```
cd apps/desktop
npm install
AIMP_APP_URL=https://app.yourdomain.com/app npm start      # try it
npm run dist:mac    # run on a Mac
npm run dist:win    # run on Windows (or CI)
npm run dist:linux
```

Locked down on purpose: no Node access from the page, sandboxed, only your own address loads in the window, other https links open in the normal browser, everything else is blocked, no camera/microphone/location. `npm test` checks those rules.

Before shipping: change `appId` in `electron-builder.yml` to an identifier you own (it cannot change later), and add code signing. Unsigned Mac and Windows apps show scary warnings. Signing needs an Apple Developer membership for Mac and a code-signing certificate for Windows.

## iPhone and Android (Capacitor)

```
cd apps/mobile
npm install
AIMP_APP_URL=https://app.yourdomain.com/app npm run set-server
npx cap add ios        # needs a Mac with Xcode
npx cap add android    # needs Android Studio
npm run sync
npm run open:ios       # then Product > Archive in Xcode
npm run open:android   # then Build > Generate Signed Bundle in Android Studio
```

`apps/mobile/ios` and `apps/mobile/android` are generated by those commands and are not in git yet.

## Store accounts and rules (check current prices and rules before paying)

- **Apple Developer Program** (needed for the App Store and TestFlight) is a yearly fee. I believe it is US$99 a year; confirm on Apple's site.
- **Google Play Console** is a one-time fee. I believe it is US$25; confirm on Google's site.
- **Apple review risk:** Apple can reject apps that are only a website in a frame. To pass, the app should offer something a phone-native feature adds (for example push notifications for new orders). That is not built. Treat store approval as uncertain until a real submission.
- **Selling inside the app:** your sellers' buyers pay on the web shop, not inside the app, which keeps you away from Apple's and Google's in-app purchase rules for the shop itself. If you ever charge sellers a subscription inside the app, those rules apply. Get advice.

## What is still needed from you
